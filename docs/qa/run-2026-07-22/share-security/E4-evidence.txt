This self-hosted build (data365, NEXT_PUBLIC_IS_CAP != "true") redirects ANY
path that isn't a recognized top-level app section straight to /login,
BEFORE Next.js page routing ever runs -- so app/not-found.tsx (which DOES
exist and renders a proper "404 / Kechirasiz, bu sahifa topilmadi" page) is
effectively unreachable for ordinary page paths on this deployment: a truly
nonexistent URL and a protected URL are indistinguishable to the visitor,
both just bounce to /login.

STATUS: flag (should, not blocker). This is intentional, deliberate code
(not a crash/500/leak) and IS what the plan confirms for /dashboard
(307->login is correct/expected there). But it deviates from the plan's own
EXPECTED bar for E4 ("a clean 404/not-found for TRULY UNKNOWN" paths) -- a
mistyped URL or a dead link silently bounces a visitor to the login screen
with no explanation, which reads as "you got logged out" rather than "that
page doesn't exist." Not a security issue (no data leak, no 500) and not
something that blocks core-readiness (recording/AI-results/no-waste), so
rated "should" for the team's backlog: either special-case genuinely-unknown
paths to render not-found.tsx, or accept the current behavior as intentional
and update the plan's own expectation to match reality.
